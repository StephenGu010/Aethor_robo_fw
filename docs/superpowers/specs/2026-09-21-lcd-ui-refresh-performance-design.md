# LCD UI 刷新性能优化设计

## 目标

在不增加整屏帧缓冲、不改变电机控制与安全门禁、不接入或修改 ARDC 控制链路的前提下，降低五向键操作到可见反馈的延迟，并让首页横向切换动画更连续。

## 已确认瓶颈

- ST7789V2 当前内部扫描配置为 60 Hz，但 SPI1 实际像素时钟为 5 MHz；280×240 RGB565 整屏纯像素传输的理论耗时为 215.04 ms。
- 首页动画以 20 ms 为更新间隔，却对根对象执行整屏失效，传输需求远大于当前串行带宽。
- 同页焦点、数值等模型变化由 100 ms 周期刷新，按键消抖完成后仍可能额外等待接近 100 ms。
- 现有双 280×24 RGB565 DMA 缓冲共 26,880 字节，符合低内存目标；增加缓冲高度不会减少整屏总传输量。

## 方案

### 1. 事件驱动视图更新

UiTask 保留 100 ms 遥测刷新周期，但在按键事件、请求受理、请求完成和显示恢复改变模型后置位 `view_dirty`。下一次 5 ms 图形服务立即执行视图映射，并在映射完成后清除该标志。

该标志只属于 UiTask，不进入中断，不改变输入消抖、STOP 优先级或电机命令发布流程。

### 2. 首页动画局部失效

首页图标动画只失效覆盖图标、角标和标题文本的固定矩形，不再失效 280×240 根对象。页面结构、非动画页面和显式页面重绘继续沿用现有失效行为。

局部矩形必须覆盖动画起止位置，避免旧图标残留；范围保持为编译期常量，不引入动态分配。

### 3. SPI 分阶段提速

第一阶段仅将 SPI1 分频从 16 改为 8，使当前 80 MHz SPI 核时钟下的串行像素时钟由 5 MHz 提升到 10 MHz。该频率低于达妙参考例程使用的 30 MHz，也远低于 ST7789V2 数据手册写周期对应的理论上限。

本阶段不修改 SPI 核时钟、极性/相位、DMA、LCD 内部 60 Hz 配置或 50 ms 传输超时。20 MHz 及更高频率必须在 10 MHz 实屏验证通过后单独实施。

### 4. 整次 LVGL 刷新统计

显示端口在 UiTask/显示中断共同遵守现有单事务所有权的基础上，累计一次 LVGL 刷新中的传输字节数，并以 `lv_disp_flush_is_last()` 标记最后一块。最后一块成功完成后发布：

- 最近一次完整刷新字节数；
- 最近一次完整刷新耗时；
- 完整刷新完成计数；
- 完整刷新失败计数；
- 由最近一次耗时换算的有效 FPS（定点十分之一 FPS）。

统计只用于诊断，不参与显示健康判定、电机控制或超时判定。显示故障、中止或同步启动失败时不得把不完整刷新计为成功帧。

## 可见诊断

LCD“诊断信息”页面显示完整刷新耗时、字节数和有效 FPS；DMA/SPI 累计错误仍保留。原有 `display_flush_last_us` 健康字段继续表示底层传输块耗时，避免改变现有应用诊断契约。

## 验证

- 先增加源码契约与主机回归断言，并确认其在生产修改前按预期失败。
- 逐项实施事件驱动刷新、局部失效、刷新统计和 10 MHz SPI，每个切片运行对应主机测试。
- 最终运行现有 UI 回归、LCD 传输测试、完整 `verify_debug_ui.ps1 -IncludeKeil` 四目标构建与 `git diff --check`。
- 本轮不烧录。真实帧率、花屏、撕裂和 SPI/DMA 错误必须在后续实屏验证中确认，软件理论值不能替代硬件验收。

## 非目标

- 不把 ARDC 数据接入 LCD。
- 不提高 UiTask 优先级。
- 不缩短电机参数编辑的按键重复周期。
- 不修改 LCD-ReadOnly、LCD-POS、LCD-MIT 的功能门禁。
- 不修改电机运动参数、保护阈值、CAN 或 USB 协议。
