# S3519 MIT 参数标定与调试指南

本文用于 `USB_BENCH_RELATIVE` 台架 Profile 的单电机、空载、低能量调试。它把“固件已经实现的软件合同”“S3519 资料给出的参考值”和“必须连真实电机后才能确认的参数”分开记录，不能作为七轴整机验收报告。

## 1. 当前已经可用的公开接口

```text
<id> bench mode <升序电机列表> mode=mit
<id> bench mode <升序电机列表> mode=pos_vel

<id> bench mit <单个电机> action=hold kp=<Kp> kd=<Kd> torque_ff=<N·m> duration_ms=<100..10000>
<id> bench mit <单个电机> action=move position=<输出端绝对角度°> speed=<输出端速度°/s> kp=<Kp> kd=<Kd> torque_ff=<N·m> duration_ms=<100..10000>
```

`bench mode` 的生命周期是：发现参数 → 发送失能 → 检查新鲜反馈、无故障、驱动已失能且输出速度接近零 → 写模式寄存器 → 读回确认 → 返回 `done`。成功后电机仍然失能，不会自动运动，也不把模式写入 Flash。

`bench mit` 的生命周期是：发现参数 → 失能与零速门控 → 切换并读回 MIT → 清故障 → 使能 → MIT 保持或 STM32 本地五次时间缩放轨迹 → 定时保持 → 失能 → 收到新鲜 disabled 反馈 → 返回 `done`。Windows 上位机只提交一次请求，不承担实时控制循环。

`bench move` 仍是自包含 POS_VEL 动作，并会在自己的状态机中切换并确认 POS_VEL。因此不要求先手工执行 `bench mode ... mode=pos_vel`；显式 `bench mode` 主要用于模式读回联调和上位机状态同步。

## 2. 资料值与本次初始值

S3519/DM3520 资料给出的 MIT 关系为：

```text
T_ref = kp × (p_des - position) + kd × (v_des - velocity) + torque_ff
```

其中位置、速度和转矩均按电机减速输出端解释。厂商资料给出的可编码增益范围是 `Kp=0..500`、`Kd=0..5`，并明确提示位置控制时 `Kd` 不能为零。厂商 MIT 示例使用 `Kp=1、Kd=1、torque_ff=0`，因此本项目把它作为首次空载调试起点，而不是已标定值。

S3519 铭牌/说明书中的额定信息可作为测试边界背景：24 V、额定输出转矩 3.5 N·m、峰值输出转矩 7.8 N·m、额定输出转速 395 rpm、最大输出转速 435 rpm、减速比 `3591/187`（约 19.20）、极对数 7。它们不能替代驱动器当前 `PMAX/VMAX/TMAX/MAX_SPD` 寄存器值；固件始终以后者的本次上电读回值作为 MIT 编码与动作拒绝边界。

首次空载命令采用以下保守起点：

| 参数 | 初始值 | 含义 | 当前证据级别 |
|---|---:|---|---|
| `kp` | 1 | 位置误差刚度 | 厂商示例，未实机标定 |
| `kd` | 1 | 速度误差阻尼 | 厂商示例，未实机标定 |
| `torque_ff` | 0 N·m | 前馈输出转矩 | 安全起点，未做转矩补偿 |
| HOLD 时间 | 1000 ms | 持续发送同一 MIT 保持目标 | 软件边界已测，机械效果未测 |
| MOVE 位移 | 5° | 相对本次上电零点的输出端绝对目标 | 首次动作建议，不是软限位 |
| MOVE 最大期望速度 | 2°/s | 五次轨迹的速度上限 | 首次动作建议，真实速度未测 |

## 3. 必须接真实电机后逐项标定的参数

以下项目目前不能凭代码或说明书声明“已正确”：

| 类别 | 每个电机需要记录的值 | 判定方法 |
|---|---|---|
| 驱动量程 | `PMAX、VMAX、TMAX、MAX_SPD` | `bench init` 后用 `show motor <id>` 保存读回；与调试助手当前寄存器逐项核对 |
| 坐标方向 | 正命令对应的实际输出方向 | 低速 1°–5° 空载动作观察并记录；不得靠软件猜测 |
| 上电零点 | 上电时输出端位置与机械零位偏差 | 用机械基准和反馈共同测量；当前 `position=0` 只是本次上电零点 |
| 外部传动 | 电机输出端到最终关节/法兰的减速比、方向和零偏 | 分别测量输出端与最终关节，建立独立映射；不要把输出端目标直接当最终法兰目标 |
| 机械软限位 | 正负方向允许角度和安全余量 | 从机械图纸与慢速实测共同确定；不得直接使用 `PMAX` 作为机械臂软限位 |
| MIT 刚度 | 每轴空载和带载 `kp` | 从低值逐步增加，记录静差、超调、振荡和峰值电流 |
| MIT 阻尼 | 每轴空载和带载 `kd` | 保持 `kp` 不变逐步增加，记录振荡衰减、噪声和发热；始终大于零 |
| 前馈转矩 | 每轴姿态相关 `torque_ff` 或重力补偿模型 | 初期保持 0；只有转矩方向、零偏和限幅验证后才逐步加入 |
| 轨迹速度 | 安全速度、实测峰值速度和到达时间 | 对比命令轨迹与 CAN 反馈，不用 Windows 串口时间推断实时性 |
| 到位门限 | 当前软件为输出端 0.5° | 根据编码噪声、减速器回差和任务精度实测后再决定是否调整 |
| 模式切换零速门限 | 当前软件为 0.05 rad/s（约 2.865°/s） | 记录失能后的反馈速度噪声；门限既要能稳定通过，也不能掩盖实际转动 |
| 反馈新鲜度 | 当前软件为 100 ms | 在目标 CAN 负载下测最大反馈间隔、抖动和丢帧，再保留充分安全余量 |
| 电气与热边界 | 母线电压、相电流/转矩限幅、驱动温度、电机温度 | 使用电源限流、调试助手和温度记录；达到任何边界立即停止 |

建议为 J1–J7 分别保存一行标定记录，不允许把一个电机的 `kp/kd/torque_ff` 直接复制成七轴验收值。

## 4. 单电机空载调试顺序

下面以电机 1 为例。每条动作使用新的非零请求编号，串口发送开启 CRLF，关闭循环发送。

### 4.1 只读与发现

```text
1 hello
2 stream off
3 show state
4 bench init 1
5 show motor 1
6 show diag can
```

进入下一步前必须看到：Profile 为 bench；电机 1 的身份、模式、量程和版本均已验证；反馈新鲜；无驱动故障；CAN 无 Bus-Off。

### 4.2 只验证模式切换，不使能

```text
10 bench mode 1 mode=mit
11 show motor 1
12 bench mode 1 mode=pos_vel
13 show motor 1
```

两条模式命令都应先返回 `ok ... accepted=1`，随后返回匹配编号的 `done ... result=completed`。切换完成后电机必须仍为 disabled。若电机正在转动、反馈过期、带故障或无法确认失能，命令应失败而不是强行切换。

### 4.3 首次 MIT 保持

固定电机本体，移除机械臂负载，电源设置保守限流，急停和断电手段保持可用：

```text
20 bench mit 1 action=hold kp=1 kd=1 torque_ff=0 duration_ms=1000
21 show motor 1
22 show diag can
```

观察并记录：使能瞬间是否冲击；保持期间位置误差、速度噪声、电流和声音；1 s 后是否自动失能；终态是否为 `completed`。出现抖动、尖叫、快速升温、异常电流或方向不符时，立即发送：

```text
23 bench stop 1
24 bench disable 1
```

### 4.4 首次 MIT 小角度移动

```text
30 bench mit 1 action=move position=5 speed=2 kp=1 kd=1 torque_ff=0 duration_ms=1000
31 bench mit 1 action=move position=0 speed=2 kp=1 kd=1 torque_ff=0 duration_ms=1000
32 show motor 1
33 show diag can
```

确认动作是平滑轨迹而非端点跳变，正方向符合预期，回到 `position=0` 后只是回到本次上电零点。保存反馈曲线中的目标位置、实际位置、速度、故障、电流/转矩估计和温度。

## 5. `kp/kd/torque_ff` 实调方法

1. 始终保持 `torque_ff=0`，先调阻抗反馈。使用 1°–5°、1°/s–2°/s、500–1000 ms 的空载动作。
2. 从 `kp=1、kd=1` 开始。若位置误差大且没有振荡，每次只小幅增加 `kp`，每次动作后自动失能并保存数据。
3. 若出现超调或振荡，先停止增加 `kp`，小幅增加 `kd`；若高频噪声、发热或阻力明显上升，则回退 `kd`。
4. 每次只改变一个参数，并记录命令、固件 commit、电机 ID、供电、负载、姿态、峰值误差、超调、稳定时间、峰值电流和温升。
5. 空载稳定后再以更低参数进入实际机构；先验证方向、零位和软限位，再做带载参数。不得直接复用空载最优值。
6. `torque_ff` 保持 0，直到输出转矩符号、TMAX、重力方向和急停清理均已验证。之后从很小的绝对值逐步增加，并始终小于读回 TMAX 和更保守的工程限值。

实调目标不是把 `kp/kd` 调到最大，而是在规定负载和速度下同时满足：无持续振荡、无异常噪声/温升、峰值电流有余量、到位误差与稳定时间达标、STOP 和自动失能始终有效。

## 6. 常见失败与定位

| 终态 | 优先检查 |
|---|---|
| `stage=discovery code=not_ready/action_failed` | CAN 接线、终端电阻、电机 ID、参数读回应答、量程字段完整性 |
| `stage=validate code=stale_feedback` | 反馈周期、CAN 接收、时间戳、所选电机是否真的在回报 |
| `stage=validate code=position_out_of_range` | 目标绝对角度与读回 PMAX；是否误把最终关节角传给输出端接口 |
| `stage=validate code=speed_out_of_range` | `speed` 与 `min(VMAX,MAX_SPD)`；单位是否误用 rpm 或 rad/s |
| `stage=mode code=timeout/action_failed` | 电机是否失能且接近零速；模式寄存器写 ACK 与读回值是否一致 |
| `stage=clear/enable code=feedback_timeout` | 特殊命令 CAN ID 是否对应 MIT 模式；驱动状态反馈是否更新 |
| `stage=motion code=timeout` | 反馈是否到达 0.5° 门限；方向、零点、机械卡滞、增益过低或速度设置 |
| `stage=hold code=action_failed` | 控制任务周期是否连续；MIT 编码范围、反馈故障和 CAN 调度 |
| `stage=disable code=feedback_timeout` | 禁用帧是否发出；驱动是否回报 disabled；必要时断电并检查驱动状态 |
| `error ... code=busy` | 前一自包含动作尚未得到终态；先等匹配 `done`，必要时用新的编号 STOP |

## 7. 分阶段验收边界

- 软件级：协议解析、量程拒绝、STOP 抢占、模式写/读回、MIT 轨迹更新、保持时长和最终失能通过主机自动化测试。
- 单电机空载级：每个电机分别完成模式往返、保持、小角度往返、STOP、故障和自动失能，并保存日志。
- 机构单轴级：确认最终关节方向、零位、减速比、软限位和带载参数。
- 七轴级：在所有单轴门控通过后，才允许做同步轨迹、负载、热、电源和急停验收。

在没有真实电机的当前阶段，只能声明软件级合同完成；表中所有实机参数仍标记为“待标定”。
