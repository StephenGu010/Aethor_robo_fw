# LCD 失败后重新检查恢复（2026-09-14）

## 现场原因

用户报告 MIT 输出轴相对 10° 动作失败，随后失去本地控制，进入“中键 重新检查”后无法重新申请，必须复位主控。

`output/lcd-output-angle-20260914/20260914T160425/motor7-failure-audit-20260914T081824.json` 保存故障现场：控制权 LOCAL_FAULT，未确认失能掩码为 0，目标电机 7；按键与显示健康，UI 原因为 NOT_READY。最后反馈显示 driver_state=0、fault=0，但速度为 -0.5372467 rad/s，已过期 322827 ms。旧中键逻辑仅重复申请前置判断；失能状态不持续反馈，因此该旧速度永久挡住 0.05 rad/s 静止门槛。

未复位情况下执行 USB STOP，`motor7-pos-probe-STOP-20260914T162059448.json` 读回新鲜失能反馈，速度变为正常零速量化格 -0.04884 rad/s，boot 仍为 34304836。这验证了应刷新反馈，而非跳过静止判断。

## 修复行为

在故障恢复页，重新检查若因未就绪、未失能或反馈过期受阻，且选中电机匹配原本地目标，中键提交该目标的 STOP。已有活动和未确认失能目标仍优先，不能把其他浏览电机混入远端停止请求。STOP 使用原执行器处理，已失能或反馈过期时只发送 DISABLE 获取新回执。

刷新完成后，返回申请本地控制并正常长按确认。故障不会自动授权，也不放宽速度、故障、失能或动作前新反馈门槛。只读配置不发送此请求。原有活动 STOP、重复按键抑制和多目标清理机制保持有效。

MIT 运行保护现在分别报告转矩超限、速度超限、温度超限、反馈异常；位置越界仍为超出范围。新增枚举值追加在原值之后。触发瞬间的反馈、原因及电机号保存在 App 的 last_mit_guard_* 字段中，不会被随后失能反馈覆盖。没有更改增益、1 Nm 转矩保护或运动边界。

## 验证范围

自动化用例复现旧的过期残余速度，并覆盖 POS/MIT 恢复、STOP 目标与去重、重新长按授权、执行器仅下发 DISABLE 后重新申请成功，以及每类 MIT 保护原因和触发样本保留。硬件侧已用不复位的 STOP 刷新验证原因。
