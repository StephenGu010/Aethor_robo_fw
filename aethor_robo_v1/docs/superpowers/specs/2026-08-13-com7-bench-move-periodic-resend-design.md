# COM7 台架相对运动周期重发设计

## 背景

当前 USB CDC 台架协议能够完成 CAN ID 1、3 的发现、清故障、使能、停止和失能。`MOVE_REL` 会为所选电机生成一次绝对位置速度目标，但 `BENCH_MOVE_WAIT` 在首批帧发完后只等待到位反馈，不再重发目标。实机执行 `3 deg`、`1 deg/s` 的双电机命令时，协议已接受运动，但在计划时长加 `500 ms` 后返回 `FAILED detail=3`；用户观察不到明显运动。旧的双电机实机控制路径会在运动和保持阶段周期重发目标帧。

## 目标

- 台架相对运动等待期间，周期重发所选电机的固定绝对目标。
- 每批目标全部发完后再开始下一批，不改变电机选择、目标角度或速度。
- 保留现有到位判定、动作超时、链路看门狗、STOP 和 DISABLE 行为。
- 首轮修复不提高 `delta_deg` 与 `speed_deg_s` 的 `3.0` 上限。
- 软件与实机闭环稳定后，再以独立增量评估将台架角度上限提高到 `10 deg`。

## 方案选择

采用“周期重发固定绝对目标”方案。`MOVE_REL` 启动时继续使用当前反馈计算一次绝对目标，并继续使用现有位置速度帧批次。`BENCH_MOVE_WAIT` 每次确认一批帧已经发送完成后：

1. 检查所选电机反馈是否有效、无故障且全部进入 `0.5 deg` 到位窗口；
2. 全部到位时按现有逻辑完成命令；
3. 尚未全部到位时，将该批帧的读取索引复位为零，使下一控制周期从第一台所选电机开始重发。

不采用“每周期重新构造目标帧”，因为绝对目标在动作期间不应变化；不采用“单发目标加额外反馈查询”，因为需要引入新的厂家查询流程，而且不能周期确认目标。

## 数据流

```text
MOVE_REL
  -> 读取所选电机当前反馈
  -> 计算固定绝对目标
  -> 构造所选电机 POS_VEL 帧批次
  -> 逐帧发送完整批次
  -> 检查到位
       -> 已到位：DONE COMPLETED
       -> 未到位：批次索引复位，继续发送
       -> 超时/故障：DONE FAILED，执行现有安全停机路径
```

## 安全边界

- 不修改 CAN ID 与 Master ID 映射。
- 不修改生产配置、方向、零点或机械限位。
- 不扩大首轮台架命令的角度和速度上限。
- 任何协议失败仍由调试脚本执行 STOP 与 DISABLE。
- 实机验证保持空载，并按 CAN ID 1、CAN ID 3、CAN ID 1+3 的顺序推进。

## 测试设计

### 回归测试

在主机 Phase 0 测试中构造已经完成电机发现与使能的台架相对运动。读取首批所选电机目标帧后，在反馈尚未到位且未超时的下一服务周期再次读取，断言仍能取得相同 CAN ID、相同位置和速度负载的目标帧。该测试在当前实现上必须因第二批目标不存在而失败。

### 软件验证

- Phase 0 回归测试通过；
- 协议、Motor Core、Platform IO、Motion 和模拟器测试通过；
- COM7 调试脚本自测通过；
- Keil 全量编译为 0 errors、0 warnings；
- 新 HEX 经校验后烧录。

### 实机验证

依次执行：

1. CAN ID 1：`3 deg`、`1 deg/s` 往返；
2. CAN ID 3：`3 deg`、`1 deg/s` 往返；
3. CAN ID 1、3：`+3/-3 deg`、`1 deg/s` 同步往返。

每阶段必须满足 `MOTION_DEBUG_PASSED`、最终失能、驱动器故障为零、CAN 无 Bus-Off，并结合用户观察确认方向、声音和机械状态。任一阶段失败即停止后续实机动作并回到诊断。

## 非目标

- 本增量不实现七轴生产运动。
- 本增量不完成方向、零点、机械限位或负载标定。
- 本增量不修改 DH、URDF 或笛卡尔控制。
- 本增量不保证大于 `3 deg` 的台架运动；`10 deg` 上限属于后续独立增量。
