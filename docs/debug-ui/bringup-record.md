# DM_TFT 接入记录

当前状态（2026-09-11）：**主控、LCD和电机7已接入，已点屏并完成只读固件刷写回读；完整实机验收尚未完成。** 下面保留各项独立证据要求，未测项目不因接通或构建通过而自动通过。最新进度见[逐阶段验收记录](acceptance-record.md)。

用户实物可辨认丝印为 `DM_TFT1_xx_01`。设计依据来自 DM_TFT-V1.1 / ST7789V2 / QT169-TSC12PG01，不能用软件构建结果确认实物版本。

## 外设与生成代码的所有权

| 资源 | 代码所有者 | 当前候选配置 |
|---|---|---|
| SPI1 | `App/Platform/lcd_st7789.c` | PB3 SCK、PD7 MOSI；发送；默认从低速点屏 |
| DMA1 Stream0 | 同上 | SPI1 TX，IRQ 优先级 8 |
| ADC1 | `App/Platform/lcd_key_adc.c` | PA5 / INP19，12 位单通道，每 5 ms 请求中断转换 |
| LCD 控制 GPIO | 平台 LCD 驱动 | PE15 CS、PD10 DC、PB11 RES、PB10 BLK |
| IRQ 转发 | `Core/Src/stm32h7xx_it.c` 的 USER 区 | SPI1 / DMA1_Stream0 / ADC，仅在 UI 开启时接入 |
| UiTask | `Core/Src/freertos.c` 的 USER 创建区 | 独立静态任务，Low，2048 个 32 位栈字 |

`.ioc` 记录七个 LCD 引脚的占用和安全初态：CS 高，复位和背光低，SPI/ADC 引脚先处于模拟输入。UI 开启后平台驱动切换复用并启用中断。SPI/ADC 句柄、MSP 和时钟选择只有平台驱动一份，不能再生成并调用 `MX_SPI1_Init()` / `MX_ADC1_Init()`。

原六任务继续由 `.ioc` 保留，UI 是条件编译的第七个任务，不能将它同时加入 CubeMX 自动创建列表，否则 UI 关闭时也可能创建任务。CubeMX 再生成后需运行架构检查、主机回归和四个 Keil 构建；本轮不宣称已验证 CubeMX GUI 往返生成。

## 上电前的固件选择

当前使用 `LCD-ReadOnly` 构建。编译支持 POS/MIT 的目标也默认没有任何有效电机台架配置，不能绕过配置和运行时授权直接运动。参数的专项验收范围以H01～H06逐项结果为准。

硬件操作记录必须写明日期、板卡/电机 ID、供电、机械负载、固件哈希、测试输入和实际反馈。没有收到失能反馈时记录“未确认”，不以命令已发出代替电机状态。
