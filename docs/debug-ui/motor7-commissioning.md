# 单电机7联调（2026-09-09）

本次仅连接电机 CAN ID=0x07、Master ID=0x17。保留七电机框架，其余六台不配置为已验证，不开放 LCD 本地运动。

## 已查明的问题

1. 首次初始化完成行使用 ProtocolEngine 上一轮 query_context 格式化验证标志，可能显示 mode=00。修复为 ArmControlTask 创建完成结果时保存四个验证掩码，随结果队列传递；随后查询/发现变化不能改写历史完成记录。新增单电机7回归覆盖。
2. 已确认 POS 模式后的禁用命令使用0x107，未获得新的反馈；此前 USB2CAN 基础0x07禁用成功。厂商本地 SDK `S3519/电机SDK/Python例程/u2can/DM_CAN.py` 的 `__control_cmd` 对特殊命令使用 SlaveID。新增 motor_compatibility.h，仅台架 ESC7 使用基础ID特殊命令，位置速度数据仍发0x107；其他电机和生产配置保持原约定。
3. 更正早期记录：bench init 并非纯读取。它读取参数后还会写入模式2并读回；不保存Flash，也不使能电机。此后将其称为初始化。

## 验证计划与边界

- 电机核心、Phase0、生产配置、文本协议引擎和五种 App 权限配置回归；Keil LCD-ReadOnly 编译。
- 校验并烧录后验证首次初始化四个掩码均为40，重复禁用必须得到实际反馈。
- 禁用预检通过后只运行一次输出轴目标0.25度、速度0.5度/秒的自包含 POS 动作。PC只读取反馈和触发停止，MCU负责轨迹；位置绝对值2度、速度20度/秒、转矩0.5Nm、温度55度为本次停止条件。它们不是最终标定配置。
- 任何失败先停止并禁用，记录结果，不自动增加动作或放宽阈值。所有命令仅针对电机7，试验请求使用独立编号，避免历史完成结果重放。
- 先前2度试验在217ms时转矩约0.52Nm，驱动状态1，超过脚本阈值后停止；转矩升高的物理原因尚未证实。

本次软件变更不提供周期性失能刷新，不延长100ms反馈有效期，不将候选参数标记为通过台架标定。
