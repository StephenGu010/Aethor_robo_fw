# 会话结束与实验配额说明实施计划

用户已明确要求增加独立结束会话按钮、解释本地占用/反馈过期、显示实验配额原因及恢复方法。本轮只修改上位机，不发送实机运动、预检、模式切换、失能或配额恢复命令。

## 设计及验收契约

- 新按钮独立于运动参数草稿；一次点击只允许读取能力、查询原事务、单次释放控制和查询释放结果。
- 原事务必须有同一编号的终态及明确失能证明；活动、未知、失能未确认、LCD/本地保护占用时不发送释放，更不能抢占控制。
- 提交前重新核对启动号、会话代次、终态编号、无活动事务及控制权；断连、STOP或页面变化取消后续步骤。未知提交保留编号，不重发。
- `owner=1`显示为“LCD / 本地保护占用”，现有协议不能区分本地控制和保护锁定；引导用户在LCD控制准备页完成恢复/释放。
- `fresh=0`明确指标准反馈缺失；功能能力不作为反馈新鲜或运动资格。
- 配额显示当前3.5或5.46 N·m边界、板端原因与恢复条件；原因5说明可能是其他故障后的统一撤销，不能推断首故障。撤销记满不等于实际超额运行10秒。
- 恢复流程保留原有人工冷却声明、新维护令牌和板端检查；不自动预检、切模式、恢复或重试。

## 实施顺序

1. 增加纯会话结束流程及单元测试，覆盖失败已失能、未确认失能、活动/LCD占用、身份变化、提交未知及重复请求约束。
2. 扩展配额解析/解释及对应测试，再逐文件增加会话面板、恢复说明和样式。
3. 全API拦截浏览器测试验证交互、错误路径、移动端布局以及禁止运动请求；运行TypeScript构建与相关回归。
4. 通过独立复审后更新已运行页面，仅浏览核验；不点击任何实机控制或配额恢复按钮。

现有仓库为未产生首个提交的分支，已有大量暂存及未暂存历史工作；本轮保留其状态，不创建混入旧工作的提交。
