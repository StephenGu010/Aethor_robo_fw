# DM_TFT 调试界面

当前 `feature/lvgl-icon-ui` 已实现图标菜单与共享视图，操作路径、全部模拟页面和内存验证见[图标界面实现说明](icon-ui-verification.md)。下面的发布基线及历史记录继续保留；图标版尚未烧录。

本目录记录 DM_TFT LCD 的软件接入、操作与验收。2026-09-14发布基线为LCD-MIT，电机7已有POS/MIT配置和有限空载验证。当前输出轴Kp=80、Kd=0.2，反馈转矩保护3.5 Nm；POS/MIT到位按输出轴0.5°。固定固件、当前操作、验证和历史记录界线以[发布说明](release-20260914.md)为准。模拟渲染不替代实屏、带载或整臂验收。

上手操作见[单电机操作指南](operator-guide.md)，完整计划进度见[逐阶段验收记录](acceptance-record.md)。

## 构建选择

工程是 `MDK-ARM/CtrBoard-H7_FDCAN.uvprojx`，保留原分支 `feature/mit-text-interface`。用 Keil 选择目标，或在固件根目录运行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\build_debug_ui.ps1 -Target LCD-ReadOnly
```

| Keil 目标 | UI / 本地运动 / MIT | 用途 |
|---|---|---|
| `CtrBoard-H7_FDCAN` | 0 / 0 / 0 | 默认关闭 LCD 功能，保留原六任务配置 |
| `LCD-ReadOnly` | 1 / 0 / 0 | 第一次点屏、按键和只读状态调试 |
| `LCD-POS` | 1 / 1 / 0 | 经配置和运行时授权的单机 POS 调试 |
| `LCD-MIT` | 1 / 1 / 1 | 经配置和运行时授权的单机 POS、MIT 调试 |

**只读目标拒绝所有本地状态变更，包括 STOP、失能、清故障、切模及申请控制权。** 它显示远端动作状态，动作停止仍由原 USB 控制入口负责。POS/MIT 目标下，执行中的中键 STOP 不要求先获得本地控制权。

后三个目标使用相同源代码和不同编译宏，不需要复制工程。生产配置禁止打开本地运动；非法宏组合在编译时拒绝。构建脚本只编译，不下载固件。Keil 路径可用 `-KeilPath` 指定。

## 五向键操作

这是 ADC 电阻分压五向开关，提供上、下、左、右和中键；不提供模拟摇杆的 X/Y 连续量。输入稳定空闲 200 ms 后才允许操作，上电按住的键不能直接提交动作。

| 页面 | 操作与显示 |
|---|---|
| 总览 | 上下选“电机列表、诊断信息、申请/释放本地控制”，中键或右键进入 |
| 电机列表 | 上下选择 ID1～7，五行滚动；中/右进详情，左回总览 |
| 单机详情 | 位置、速度、转矩、温度、反馈年龄、实际模式；上下切换底部动作项，中/右进入草稿，左返回 |
| 本地控制检查 | 申请被拒绝时显示模式、参数、反馈和配置；中键重新检查，右进电机详情，左返回 |
| 位置读值 | 在电机详情底部选“位置读值”，中/右进入；显示RID50、RID51原始值及各自样本年龄，左返回 |
| 诊断 | 中/右/上下翻诊断子页，左回总览；含 ADC、输入故障、DMA、控制时序、CAN/USB 丢弃和资源余量 |
| 草稿 | 上下增减当前字段，右切字段，中键进预览，左取消；这里只编辑参数 |
| 二次确认 | 先松开进入页面的中键，再连续按住中键 800 ms 才提交；左键取消 |
| 执行状态 | 显示受理、动作阶段、STOP 请求和清理进展；禁止换电机和编辑 |
| 结果/故障 | 中/左已读返回，右进诊断；区分“反馈已确认失能”和“失能未确认” |

POS/MIT 目标下，只要当前有动作或待执行请求，中键的按下事件优先提交 STOP。STOP 不走 800 ms 二次确认，也不依赖当前焦点。普通按键事件积压时，单独保留中键停止事件；它不能授权或触发运动。

若结果存储已满或上一笔 STOP 尚未完成，新的停止意图仍会被独立锁存，由控制任务处理。屏幕显示“停止已锁存 / 等待反馈”，只有所有相关目标在 STOP 之后的新鲜反馈都明确为失能且无故障时才显示确认；故障态的“未使能”不能算作已确认失能。旧结果保留，清理失败时仍保持控制锁定。

确认计时要求连续稳定输入。短暂不确定值会重新累计长按时长；过期采样、长期无效输入和卡键会撤回健康状态。正常解锁后的方向键允许持续重复输入，中键及未解锁按键保留10秒卡键检测。错误恢复后不会自动重发先前的动作。

## 数值与动作含义

屏幕位置和速度显示 `°`、`°/s`；请求合同内部使用电机输出轴 `rad`、`rad/s`，转矩为 `Nm`。当前位置基于电机本次上电参考，不等于已标定机械臂关节坐标，也不自动换算末端法兰减速比。

未收到的数据显示 `--`。已收到但不再新鲜的数值明确标记过期；没有读回实际模式时显示未知。POS 草稿在标准反馈过期时显示“动作前 --”“目标未知 / 等待反馈”，仍可编辑相对位移。控制任务在失能预检查取得新鲜反馈后计算绝对目标，并重新检查范围及参考代次；队列请求有效期仍在受理和控制任务开始执行时检查。

模式2电机失能后不持续上报标准反馈，因此正常远端空闲状态下，申请本地所有权与 POS 的800ms确认允许反馈过期，但仍要求已核验身份、范围、模式、有效台架配置、服务健康，且没有已知使能、超速或故障。所有权申请不发送控制帧。每次本地 POS 提交后先发送失能指令，等待晚于此次预检查起点的新鲜失能反馈，再校验速度、故障、绝对位置范围，最后进入原有切模、清错、使能、运动和失能清理流程。未收到反馈则超时失败，不能使用寄存器值替代。反馈过期不再改变坐标参考代次；模式核验变化或配置更新仍会改变代次并撤销旧请求。

模式2的所有权申请/释放（包括已恢复健康的LOCAL_FAULT）在没有待确认清理目标时允许标准反馈过期；仍检查已知失能、静止、无故障、身份与有效配置。原清理目标必须收到晚于失败尝试的新鲜、无故障、静止失能反馈后才清除待确认标记；控制任务只在执行器空闲时保留这一确认，不自动改变授权。快照将待确认目标发布给界面；检查页中键在有待确认目标时发送STOP重试，否则重新检查并进入人工确认。MIT、切模、清故障和显式失能仍保留原有反馈要求。静止门限与执行层一致为0.05rad/s，以容纳当前12位、±200rad/s编码的零速量化值约±0.04884rad/s。

新增的位置读值页暂不标注度或弧度，等待实际单位核对。只读台架版自动发现电机7后，由主控空闲时交替读取0x50/0x51；其他目标不随页面选择自动查询。寄存器位置有效并不代表速度、转矩、使能或故障反馈有效，也不能用于解锁本地动作。此前0xCC查询没有回包的记录保留，未通过提高过期阈值掩盖。

- **POS 移动**：相对角度以1°增减，速度以0.1°/s增减，均在有效边界处截断；沿用固件已有 POS_VEL 动作与退出清理。
- **MIT 保持**：使用开始时的反馈位置作为参考，保持时长受台架配置限制，结束清理失能。
- **MIT 移动**：固件内部生成有界五次轨迹；LCD 提交一次请求，不逐周期生成位置命令。
- **MIT 参数**：编辑 Kp、Kd、保持时间；首版 `torque_ff=0`，不能在 LCD 上修改前馈转矩。
- **切模/清故障/失能**：走统一控制任务和前置条件检查。失能操作需要新的失能反馈才能被确认。

切模确认页显示“当前实际模式 → 请求模式”。远端多电机动作显示实际参与目标，中键停止沿用活动动作的完整清理范围，不额外加入当前浏览选中的其他电机。

## 运动配置与恢复

通用源码的 `DebugUiMotorProfile` 默认无效。LCD-POS按电机7完整发现结果生成POS范围；LCD-MIT显式打开对应POS及MIT配置。内部原始位置边界为±PMAX，LCD按已核对的19.2032比值换成输出轴范围；速度受min(VMAX,MAX_SPD)约束。预计目标还须满足当前位置加相对量后的绝对边界。发现缺失或范围变化会拒绝或使旧预览失效。当前协议范围不是机械标定范围；只读及生产目标不安装这些台架运动配置，其他电机仍须明确配置。完整坐标说明见[输出轴契约](output-angle-contract-20260914.md)，后续增益和到位修正见[最新MIT记录](mit-output-stiffness-20260914.md)。

主机测试中的合成配置只用于自动化验证，不能复制成电机标定数据。电机7有限空载POS/MIT证据见[阶段交付](delivery-status.md)，更换电机后重新适配和验收。

本地控制有独立授权代次，正常空闲、编辑和成功动作后持续保留，直到手动释放；取消原30秒空闲超时。异常健康撤权、失败锁定、STOP和逐动作失能收尾仍有效。USB 与 LCD 请求使用“来源、代次、请求号”三元身份，避免相同数字请求号互相覆盖。请求进入邮箱成功不等于动作成功；界面继续等待受理和终态。

UI 和 Protocol 服务各有健康期限。任一路超过 150 ms，控制任务独立执行本地动作的停止/清理；显示任务恢复不代表电机已失能。若界面显示“失能未确认”，先处理反馈链路与故障，待新鲜反馈和控制状态恢复后重新申请本地控制；不得复用此前的草稿或确认按键。

## 自动化验证和页面预览

在固件根目录执行完整软件回归：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\verify_debug_ui.ps1 -IncludeKeil
```

不带 `-IncludeKeil` 时运行主机行为、架构、配置和实际 LVGL 渲染检查。工具路径可用 `-Compiler`、`-Python`、`-KeilPath` 覆盖；`ExecutionPolicy Bypass` 仅作用于该进程。

日志和汇总位于 `Tests/host/build/verification/`，Keil 原始日志位于 `Tests/host/build/keil/`。实际 LVGL 的模拟页面位于 `Tests/ui/artifacts/`，图像为 280×240，标题带“模拟”；它们证明软件绘制结果，不证明真实屏幕方向、颜色或电气时序。

最终 map 检查同时核对双缓冲、静态内存池和各任务已知调用链。控制任务的静态栈已扩展为 1280 个字（5120 B）；调用图中的间接调用仍有未知项，后续硬件验收还需读取实际栈高水位。

库固定为 LVGL v8.3.11，源包信息在 `Middlewares/Third_Party/LVGL/UPSTREAM.json`。SPI/ADC 补充文件与现有 HAL 同为 1.11.3，来源和逐文件哈希在 `Drivers/STM32H7xx_HAL_Driver/LCD_HAL_UPSTREAM.json`。字体来源、子集和许可证保存在 `Ui/fonts/`。
