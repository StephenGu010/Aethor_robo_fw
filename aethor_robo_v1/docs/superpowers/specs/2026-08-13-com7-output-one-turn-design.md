# COM7 输出轴一圈分阶段调试设计

## 目标

在电机空载、COM7 正常且 CAN ID 1、3 已连接的条件下，依次完成：

1. CAN ID 1 输出轴单独转一圈。
2. CAN ID 3 输出轴单独转一圈。
3. CAN ID 1、3 输出轴同时各转一圈。

S3519-1EC 使用说明书规定，位置和速度命令表示 19.2:1 减速后的输出轴量。因此一圈命令量为 `360 deg`（`2*pi rad`），不得再次乘以 19.2。

## 运动序列

当前台架协议单次相对角度上限为 3 deg。每圈拆成 120 个 3 deg 小步：

| 阶段 | 电机 | 每步角度 | 步数 | 累计角度 |
| --- | --- | ---: | ---: | ---: |
| 1 | ID 1 | +3 deg | 120 | +360 deg |
| 2 | ID 3 | +3 deg | 120 | +360 deg |
| 3 | ID 1、3 | -3 deg | 120 | -360 deg |

第三阶段采用反向一圈，使两台电机返回接近初始位置。若第三阶段继续正转，两台累计目标将接近 `4*pi rad`，超过当前约 `12.5 rad` 的 PMAX，禁止执行。

速度固定为 3 deg/s。每个小步必须等待固件返回 `ACK` 和 `DONE COMPLETED` 后才能发送下一步，不允许批量预发。

## 脚本边界

新增一个专用 PowerShell 脚本，复用现有 `aethor-arm-ascii-v1` 帧格式和 CRC-16/CCITT-FALSE 规则。脚本负责：

- 独占打开 COM7，完成 HELLO 和会话握手。
- 对当前阶段的电机执行 `INIT_MOTORS`、`CLEAR_FAULT` 和 `ENABLE`。
- 按上述序列逐步发送 `MOVE_REL`，并在等待期间持续发送 HEARTBEAT。
- 每 10 步输出一次阶段进度，避免刷屏。
- 阶段完成后执行 `STOP`、`DISABLE` 并读取 `GET_MOTORS`、`GET_DIAG`。
- 前一阶段成功后才进入下一阶段。

脚本不修改固件、不改变协议限幅、不写电机参数、不切换 CAN ID 或 Master ID。

## 故障处理

出现以下任一情况时立即停止后续步骤：

- COM7 打开、读写或 CRC 校验失败。
- 设备返回 `ERR`、`DONE FAILED` 或请求超时。
- INIT、CLEAR_FAULT、ENABLE、MOVE_REL、STOP、DISABLE 任一步失败。
- 会话心跳失败或设备链路看门狗触发。

异常路径对当前阶段电机依次执行尽力而为的 `STOP` 和 `DISABLE`，保留原始错误并退出。脚本关闭串口前不得继续到下一阶段。

## 自动化验证

在连接实机前，脚本自测至少验证：

- CRC 标准向量和帧解析。
- 三阶段电机列表、方向、步数和累计角度完全匹配设计表。
- 每圈恰好 120 步，每步绝对值不超过 3 deg。
- ID 1、ID 3 单独阶段和 ID 1、3 同步阶段的速度列表长度正确。
- 第三阶段方向与前两阶段相反。
- 默认运行必须显式携带实机执行开关，避免双击后直接运动。

## 实机完成条件

只有同时满足以下条件才报告某阶段完成：

- 120 个 MOVE_REL 请求全部收到 `DONE COMPLETED`。
- STOP 和 DISABLE 成功。
- 最终驱动故障为 0，CAN Bus-Off 为 0。

串口协议完成不等于肉眼运动已确认。最终报告分别记录串口闭环结果和用户观察到的实际输出轴运动状态。
