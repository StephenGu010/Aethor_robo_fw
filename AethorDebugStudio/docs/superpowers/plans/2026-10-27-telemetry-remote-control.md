# 反馈工程单位与远程控制实施计划

> 使用 subagent-driven-development 分配边界明确的实现与独立复核；不执行实机动作。

**目标：** 修正待机主位置通道，支持有依据的工程单位与明确标注的估算速度，并接入复用板端保护的上位机参数和单轴调试操作。

**架构：** 固件负责真实采样、样本身份和安全准入；网关负责白名单请求、独占串口和事务回执；React负责草稿、单位、数据来源及结果展示。

**技术栈：** STM32H723 C/Keil、主机GCC、.NET8、React19/TypeScript7、Playwright。

## 1. 核对反馈来源

- [ ] 对照本地厂家手册、SDK及历史0xCC原始日志，记录可用信号与版本限制。
- [ ] 核对RID50、内部比19.2032及ID7法兰总比44.8的实际代码与历史配对证据。
- [ ] 不重复已证明无效的带电控制挑战，不扫描未公开寄存器。

## 2. 工程单位和估算速度

- [ ] 固件 `App/Motor/motor_runtime.*`、`motor_idle_position_app.inc`、`Ui/debug_ui_view.c` 及布局文件新增显示专用换算/时间信息；保留标准反馈mask。
- [ ] 先增加失败测试：`p_m=19.2032 rad` 应为输出轴1 rad；`p_m=44.8 rad` 应为法兰1 rad；恒零RID51不得成为主角度；重复/过期/换boot样本不得产生有效差分速度。
- [ ] 网关 `Contracts.cs`、`Protocol.cs` 与前端 `feedbackStatus.ts`、`useStudio.ts`、`Chart.tsx`、`Analysis.tsx` 同步工程字段、坐标标签与来源。
- [ ] 运行 `python Tests/host/run_idle_feedback_tests.py`、新增位置测试、LVGL渲染和前端测试，核对未知值、负值、零值及断线。

## 3. 远程参数和单轴流程

- [ ] 核对 `DebugUiRequest`、应用请求入口及协议引擎，设计最小白名单适配；不得从通用bench接口绕过LCD专有保护。
- [ ] 先写拒绝路径测试：旧固件、过期反馈、轴号错配、控制权占用、非法单位/数值、重复点击、错误回执、超时不得重发。
- [ ] 补齐板端适配、.NET请求/回执跟踪和页面动作；参数编辑与实际写入分离，显示能力、范围、下发状态和失败原因。
- [ ] 运行固件相关主机集成、网关测试和浏览器拦截测试；测试不可连接真实COM执行控制。

## 4. 集成与交付

- [ ] 独立审查单位与安全门，修复发现后跑针对性回归。
- [ ] ARM重建、冻结新工件并验证HEX/ELF一致；保留旧部署记录。
- [ ] 更新上位机并检查真实页面，仅运行只读采集。
- [ ] 分别报告软件通过、部署状态、可用实测信号及仍受驱动能力限制的项目。
