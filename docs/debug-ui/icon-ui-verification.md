# LVGL 图标界面：实现与软件验证

2026-09-14。发布顺序：先将文字界面基线 `f33fec1` 推送并核对 GitHub `main`，再在 `feature/lvgl-icon-ui` 实现本页所述图标界面。历史可回退工件仍在 `firmware/2026-09-14`。本次没有烧录、串口命令或电机试转。

## 操作路径

1. 首页上下选择电机、诊断、申请/释放本地控制，中键或右键进入。
2. 电机列表选择 ID，中/右进入详情。详情显示输出轴大数值；中/右进入图标操作菜单，进入菜单不提交请求。
3. 菜单分两屏，每屏四项。上下按顺序循环，左返回详情，中/右进入。第一屏是 POS移动、MIT保持、MIT移动、切换POS；第二屏是切换MIT、清除故障、请求失能、位置读值。
4. 运动草稿上下调值、右键换字段、中键查看确认。确认页必须先松开中键，再按住满800 ms。草稿/确认取消回操作菜单；申请/释放保留其原入口逻辑。所有运行时门控仍由模型和应用执行层检查。
5. 运行中中键立即请求 STOP，不依赖菜单焦点。显示的 ID 来自活动快照；结果与“反馈是否确认失能”分开呈现。已读返回详情；右键进入诊断。
6. 只读固件显示锁定原因，拒绝所有本地控制请求；远端运动仍由 USB 入口控制。故障恢复继续使用控制检查与 STOP 反馈刷新路径。

五向键物理映射未改：LEFT→屏幕下、RIGHT→屏幕上、UP→屏幕左、DOWN→屏幕右、中键不变。屏幕底栏按屏幕方向说明操作。无触摸输入。

## 组件复用与内存策略

复用已锁定的 [LVGL v8.3.11](https://github.com/lvgl/lvgl/tree/v8.3.11) 原生 label、对象样式和 `LV_SYMBOL_*` 图标；未引入额外页面管理框架。图标来自既有 Montserrat 字体，新增原版28号字体用于数字。上游文件摘要与许可见 `Middlewares/Third_Party/LVGL/SOURCE_MANIFEST.json` 和 `LICENCE.txt`。

中文沿用 Noto CJK 裁剪字体，344字形、4 bpp、36701 B位图；来源及 OFL 许可见 `Ui/fonts/SOURCE.json`、`OFL.txt`。字体与图标为只读资源，主要占 Flash。未加入图片解码器、全屏位图或动画资源。

模型保留原页面编号，末尾追加 ACTIONS。视图共用一套根对象、标题/底栏、七对文本/图标槽及确认条，切页不创建或销毁页面。稳定文本存储避免向 LVGL 传递栈字符串；定制模板只更新所需槽位，避免默认布局与模板相互覆盖造成重复刷新。

| 项目 | 发布基线 | 图标版 | 口径 |
| --- | ---: | ---: | --- |
| LVGL池预留 | 65536 B | 32768 B | 固件静态数组与链接区 |
| 双DMA缓冲 | 26880 B | 26880 B | 2×280×24×RGB565 |
| 主机场景结束池占用 | 41256 B | 9680 B | 包括池管理开销，非MCU总RAM |
| 主机共享视图结构 | 多页常驻 | 2592 B | GCC主机指针大小，不外推ARM布局 |
| 当前屏子对象 | 每页各自创建 | 17 | 另有1个根对象；LVGL内部对象另计 |

LVGL池位于 `0x24008000–0x24010000`；DMA区仍为 `0x24000000–0x24008000`；后续AXI RAM从 `0x24010000` 开始。主机切页采样不是分配瞬间峰值；MCU总RAM以四目标map为准。实机栈余量、SPI时序和控制周期尚待后续独立硬件验证。

## 可复现检查

在固件根目录使用 Windows PowerShell：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools/verify_debug_ui.ps1 -IncludeKeil
```

脚本运行架构、输入/模型/应用、只读、DMA、显示健康、30分钟逻辑压力及四目标构建，并保存 `Tests/host/build/verification/summary.json` 和 `memory-layout.json`。验证前后记录构建输入摘要，防止并行修改污染结果。

真实LVGL渲染使用 `Tests/ui/run_ui_render_smoke.ps1`，检查实际字体字形、文本宽高、画面尺寸和非重复像素；反复切页1212次，检查对象数恒定和池占用不增长，最后单独触发OOM并验证局部退出和DMA缓冲所有权。模拟数据明确标记为“模拟”，与电机7运行参数无关。

全部 PNG 与 RGB 摘要位于 `Tests/ui/artifacts`。导出可离线查看的全页画廊及联系图：

```powershell
python Tests/ui/export_icon_gallery.py --output D:/download/TCG/output/lcd-ui-implemented-20260914
```

这些图来自当前固件视图代码及 LVGL 软件光栅器，不是概念图，也不是LCD实拍。软件通过不等同于硬件验收。

## 本轮最终结果

27项检查全部退出0，四个Keil目标均为0 Error(s)、0 Warning(s)，构建输入在验证期间未变化且打包前再次核对摘要。可移植摘要和三个LCD预览HEX见[独立预览工件](../../firmware/2026-09-14-icon-ui-preview/README.md)。

| 目标 | 静态RAM：RW+ZI | 较发布基线减少 | Code+RO |
| --- | ---: | ---: | ---: |
| 默认无LCD | 98680 B | 0 B | 93884 B |
| LCD-ReadOnly | 173904 B | 45120 B | 308856 B |
| LCD-POS | 173904 B | 45120 B | 312528 B |
| LCD-MIT | 173904 B | 45120 B | 312652 B |

LCD静态RAM减少约44.1 KiB（20.6%）。相应LCD-MIT的Code+RO从249596 B增至312652 B，增加63056 B；主要代价是复用完整Montserrat28大号数字字库。该项是代码与只读数据的链接统计，不是HEX文本文件大小。内存池减半与字体Flash增加分别报告。

63张不同的280×240页面全部通过字形、文字宽高及像素检查，并人工查看六张完整联系图。覆盖所有12种模型页面、八个动作焦点、三类诊断、模式/字段变体、未知/过期、超界拒绝、远端多目标、STOP锁存及停止/取消/故障终态。1212次实际LVGL更新保持17个屏内子对象，暖机后池占用不增长；刷新后采样最大9680 B，OOM局部退出通过。30分钟逻辑压力测试覆盖八个菜单焦点，零本地请求的拒绝场景回归通过。

初轮全量检查发现显示任务的恢复重绘仍引用旧页面数组；已改为共享根对象，重新通过显示恢复、DMA等待期间STOP和完整27项检查。最终日志在 `Tests/host/build/verification`，生成的全页画廊在导出目录。
