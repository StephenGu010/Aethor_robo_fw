# 示波器诊断与设备调试入口（2026-10-26）

本次只修改上位机和本地网关，没有修改或烧录主控固件，没有发送电机STOP、失能、使能、运动、清故障或参数写入。

## 查到的原因

1. COM4的USB文本查询曾正常返回。实机诊断回执见 `artifacts/scope-diagnostics-first.json`：
   - ID7：`state=absent age_ms=3986643`，最后一次电机反馈约66分26秒前。
   - ID7主控配置：方向、减速比、位置和运动限值均为`?`，`verified=00`。这些字段不能作为当前驱动模式、输出轴映射或安全运动资格。
   - CAN累计计数：`rx=12549 tx=12549 drop=0 error=0 busoff=0`。单次累计数不能证明当前CAN总线正在更新。
   - `show state enabled=00`是控制器公开状态，不能替代电机的新鲜失能反馈。
2. 固件的`show motor`读取缓存，本身不产生电机CAN反馈。前端把缺失/过期反馈保留为未知，因此没有真实曲线可绘制。没有证据进一步区分电机供电、连接或反馈触发机制的具体现场原因。
3. 原图表只按“有没有样本对象”决定画图。即使所有信号都是null，也会显示空网格。现改为按当前可见信号的有限数值判断，显示“等待有效采样”；真实零值继续绘图，隐藏全部信号时提示恢复图例。
4. 随后USB设备消失，最后成功查询时间为17:26:14（UTC+8），Windows串口枚举为空，COM4返回“指定不存在的设备”。现场原因尚未确认。该次状态见`artifacts/usb-disappearance-state.json`。
5. 热拔插时SerialPort.Close也可能抛出异常，旧清理顺序会跳过connected=false。新增保证执行的会话清理和离线回归，关闭失败仍释放会话并拒绝未发送的排队请求。

## 已接入的操作

进入“真实设备 · 诊断调试”→“手动调试”。默认连接仍只发送查询，页面加载不发送电机动作。

| 操作 | 实际内容 | 本次验证 |
|---|---|---|
| 读取配置与CAN诊断 | `show config N`、`show diag can`、`show state`、`show motor N` | COM4真实只读回执已取得 |
| 停止选中轴 | 一次`bench stop N` | 虚拟传输及浏览器拦截验证，未执行实机动作 |
| 停止全部轴 / 顶部STOP | 一次`bench stop 1,2,3,4,5,6,7` | 同上 |
| 失能选中轴 | 承托声明后，一次`bench disable N` | 同上 |

STOP遵循既有固件策略，反馈不足时可能转失能；软件STOP不能代替硬件急停。失能撤去保持力矩，负载需要独立承托。没有自动追加失能。

运动、使能、模式切换、Kp/Kd下发、驱动参数写入和保存均未开放。单轴静载与带载POS的专用LCD保护不能通过通用MIT命令冒充。现有离线参数页继续保留。

## 接口与回执规则

- 同源`POST /api/debug`，请求字段仅`operation`、`motorId`、`loadSupported`；操作白名单为`diagnostics`、`stop`、`stop-all`、`disable`。未知字段、无效轴号和未声明承托的失能请求直接拒绝。
- 唯一串口工作线程发送，STOP优先于尚未发送的诊断，队列有界，操作前冻结轴号和作用范围。
- 每次连接使用非零随机起始请求号，事务按请求号、路径、接收/终态顺序和电机掩码校验。
- 单次动作最多等待4秒。超时、解析失败和断连显示结果未知，不自动重发、不自动重连。HTTP客户端不重试动作。
- 最近10个完成/未知事务回执保存在当前网关会话缓存中，浏览器刷新仍能读取；重新连接或重启网关会清空缓存。
- `completed`仅表示设备软件回执。本版回执的`feedbackConfirmed`保持false，不据此认定物理停止或失能。
- 示波器读取主控缓存约1 Hz，仅适合慢变化观察；不能用来判断毫秒级瞬态、力矩峰值或控制响应速度。
