# 方案 B：参考 Astra 的简洁菜单设计

日期：2026-09-14。方案 A 保留为固件分支 `feature/lvgl-icon-ui` 的提交 `2d801f9`，其HEX、63页真实LVGL预览和文档均不替换。本目录是第二版设计产物：55页PNG、全页画廊、可打印联系图及操作/架构说明。图片由Pillow绘制，所有读数都是模拟示例；本轮没有修改、编译或烧录第二版固件。

## 参考依据与取舍

用户提供的仓库地址目前重定向至 [AstraThreshold/oled-ui-astra](https://github.com/AstraThreshold/oled-ui-astra)。本轮读取源码提交 `88716a62f84c41838458fd159841fe67e6a86f87`。源码仅作为研究参考保存在独立目录。

| 已核对的参考机制 | 方案 B 的应用 |
| --- | --- |
| `Menu` 的 parent、childMenu、selectIndex，以及 cameraPosMemory | 菜单树；每页记住焦点和滚动位置；返回恢复原行 |
| `Tile` 横向图标、`Selector` 四个L形角框和底部标题 | 首页保留电机、诊断、本地控制三个入口；中央突出当前项，两侧预示相邻项 |
| `List` 纵向排列、圆角反白选择框 | 电机、动作和参数全部使用一致列表；每屏最多五行，滚动条表示位置 |
| `Widget` 中实际存在的 Slider、PopUp、CheckBox | 数值用小弹窗编辑，模式用列表选择；状态变更使用专用确认弹窗 |
| `Launcher` 统一处理输入、打开/关闭、Selector和Camera | 一个导航控制器；控件仅编辑草稿，不直接调用运动接口 |

源码路径：`Core/Src/astra/ui/item/menu/menu.h`、`item/selector/selector.cpp`、`item/widget/widget.h`、`ui/launcher.cpp`。[官方介绍](https://github.com/AstraThreshold/oled-ui-astra/wiki/astra-UI%E4%BB%8B%E7%BB%8D-%E2%80%90-astra-UI-Introduction)解释了这些概念，但旧介绍中的“Widget尚未实现”已与所读源码不同，因此按当前源码核对。

本轮选择“借鉴Astra的结构和外观，继续使用现有C/LVGL”路线。直接移植整个C++框架会增加与当前C工程、输入HAL和对象生命周期的适配工作；仅把方案A改成黑白则不能解决参数与返回路径的问题。方案B同时调整信息结构和操作方式。

Astra仓库标注GPL-3.0。本方案未复制其源码、图标或位图；图标复用上一轮自行绘制的线图，菜单和控件设计独立绘制。保留来源链接，不把参考库的固件体积当作本项目内存实测。

## 菜单树

```text
首页 Tile
├─ 电机 List
│  └─ 电机 01…07：同一套模板，仅更换目标ID
│     ├─ 状态详情：模式、失能、位置、速度、转矩、温度、反馈年龄
│     ├─ POS移动：角度 / 速度 / 预览并执行
│     ├─ MIT移动：角度 / 速度 / Kp / Kd / 保持时间 / 预览并执行
│     ├─ MIT保持：Kp / Kd / 保持时间 / 预览并执行
│     ├─ 工作模式：POS / MIT → 切模确认
│     └─ 恢复与失能：清故障 / 请求失能 / 位置寄存器 / 控制检查
├─ 诊断 List
│  ├─ 按键与显示
│  ├─ 调度与通信
│  └─ 系统资源
└─ 本地控制
   ├─ 权限未获得：检查 → 申请确认
   └─ 权限已获得：释放确认

数值编辑、执行确认、拒绝原因、终态结果为共享弹窗。
运行态为全局优先页面：打断菜单或弹窗，展示真实活动目标和STOP。
```

与方案A相比，电机选择后直接进入操作列表，状态详情成为列表首项。这样执行动作少经过一层详情页；状态查看仍可一步进入。MIT保持列表不显示无用的角度、速度字段，固定零相对位移；不要把隐藏字段当作额外运动指令。

## 五向键合同

以下方向均为屏幕逻辑方向。现有物理映射继续保持：LEFT→屏幕下、RIGHT→屏幕上、UP→屏幕左、DOWN→屏幕右、中键不变。

| 场景 | 上/下 | 中键 | 左键 | 右键 |
| --- | --- | --- | --- | --- |
| 首页Tile | 前/后入口，三项循环 | 打开 | 保持首页 | 打开 |
| 普通List | 前/后行，边界停止 | 打开当前项 | 返回父页、恢复父焦点 | 打开当前项 |
| 参数List | 选择字段/预览行 | 字段弹窗或执行预览 | 放弃当前动作草稿，回电机操作列表 | 与中键相同 |
| 数值弹窗 | 增/减当前字段 | 保存到草稿，回原字段 | 取消本字段修改，回原字段 | 无操作，防止误切字段 |
| 执行确认 | 无操作 | 先松开，再连续按住800 ms | 取消，回原列表及原行 | 无操作 |
| 运行中 | 无编辑作用 | 立即请求STOP | 不离开运行页 | 无操作 |
| 结果/故障弹窗 | 无操作 | 已读，回该电机操作列表 | 同中键 | 打开诊断，返回后仍能找到原电机 |
| 状态/诊断叶子页 | 无操作 | 无操作 | 返回所属列表 | 无操作 |

首页按2026-09-15确认的操作改为左右循环选择横向图标，中键或下键进入；其余列表保留上下选择、左返回、中/右进入。首页下键只有新按下事件可进入，重复事件不触发进入，上键无动作；物理方向映射保持不变。不照搬Astra两键短按选择、长按进退的物理操作。长按只承担提交确认，避免与导航长按混淆。执行确认的800 ms从一次明确松键后开始；松手、中断、输入无效或目标/授权变化都清零。保存字段的中键不能穿透到下一层确认。

从“恢复与失能”进入控制检查时，返回原恢复列表；从首页进入时返回首页。使用一个临时返回节点记录入口，不强行改变菜单树的静态parent。结果弹窗回操作列表是B版明确的新设计，区别于A版结果回详情。

失能未确认弹窗提供直接入口：中键进入控制检查，左键回操作列表，右键诊断；三个入口均不清除锁定。诊断与寄存器叶子页没有选择框或可执行按钮，避免让数据行看起来像动作。

## 控制合同与异常展示

- 视图仅读取快照。列表选择和弹窗保存只更新草稿；只有确认完成才调用既有模型请求入口，随后经邮箱由应用唯一所有者执行。
- 显示输出轴单位和本次上电零点，维持当前坐标转换。示例M07使用Kp=80、Kd=0.2；实际默认值、步长、范围来自校验后的profile，不从设计图硬编码。
- 对越界、反馈过期、身份/模式未校验等，弹出具体拒绝原因并保留草稿；不提交请求，不为了显示数值使能电机。
- 当前值未知显示“--”；历史值必须带“上次”和年龄。图中只有一个已知电机的样例，不代表当前在线设备清单。
- 切模显示选择项与已读回模式的区别，不使用立即生效的开关；清故障、失能、申请/释放也都独立确认。
- 运行页ID与模式由活动快照提供，不用当前浏览焦点代替。STOP先于普通导航、弹窗和动画处理，发送后仍需等待清理及反馈确认。
- “动作完成/停止/取消/失败”与“失能是否确认”分别显示。失能未确认保持锁定，进入控制检查刷新；不会因关闭弹窗自动解锁或重发。
- ReadOnly保持原编译边界：不能申请、释放、切模、清故障、失能或STOP。运行页明确“只读监视，本屏不能发送STOP”。

## 显示层与内存规划

保留LVGL8.3.11、RGB565和既有DMA双缓冲。黑白是本版视觉选择，不意味着280×240屏自动变为1 bpp显存。

| 模块 | 规划职责与存储 |
| --- | --- |
| MenuSpec | const节点表存Flash；节点ID、父节点、类型、条目范围、操作映射；不使用vector/string/new |
| NavigationState | 当前节点、选中电机、每页焦点/首行、一次性返回节点；同级返回不丢位置 |
| DraftWidget | 当前字段、进入弹窗前的备份值、编辑值；中键只写回草稿；左键恢复 |
| Selector / Viewport | 一套选择框、当前位置与目标位置；最多五个可见列表行或三个图标槽 |
| SharedOverlay | 一个弹窗根对象，复用标题、三行说明、数值/滑条、确认条；不截取父页位图 |
| Model / App Bridge | 继续使用原输入验证、请求/终态、STOP抢占、权限epoch与反馈门控；原运动参数和算法不改 |

优先保持32 KiB LVGL池、26880 B DMA双缓冲。导航与弹窗新增状态设为不超过512 B的设计预算；LVGL对象目标不超过24个应用对象。以上是实现验收目标，不是已经测出的用量。

共享三类界面：Tile、List、Overlay，加状态/运行模板。可通过隐藏共享槽与更新文本实现，七台电机和多种动作不各自常驻一棵对象树。采用裁剪中文和仅覆盖数字、单位、标点的小号数值字库，避免B版再次导入完整大号字体。图标用少量线段或1 bpp小图，生成图、GIF及网页不会编入固件。

动画仅用于闲置时的焦点/滚动过渡，建议120–160 ms、每20 ms更新位置；显示故障时立即取消，运行STOP路径不等待动画完成。背景不做全屏模糊、截屏或大范围透明混合。截图的点阵背景是弹窗层次示意；真正实现以共享对象和简单遮罩复现，并验证实际重绘耗时。

## 页面与后续实现验收

`manifest.json`枚举55个设计状态；HTML提供模板筛选和“打印全部”。MIT保持的Kp/Kd/时间数值弹窗复用MIT移动的同字段弹窗，只更换父标题和返回节点；七个电机、三类拒绝原因等同构页面不为每个组合重复绘图。

本轮检查：所有PNG为280×240、文件可解码、55幅像素不同、651次文字边界测量通过，逐张检查联系图。该检查证明设计工件可用，不能证明固件编译、内存预算或板上时序。

第二版固件落地时必须独立分支，并验证：完整菜单路径和焦点恢复；字段保存/取消不提交；确认松键与800 ms连续计时；MIT保持隐藏字段语义；运行STOP覆盖弹窗与动画；所有ReadOnly变更入口零请求；目标与授权变化取消确认；模式读回；失能未确认不解锁；55状态及其字段变体真实LVGL渲染；反复进退弹窗无泄漏；map确认RAM/Flash和四目标构建；继续不烧录，除非后续明确要求。
