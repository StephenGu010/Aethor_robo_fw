## 基线与构建

实际使用 GCC 14.3.0、Keil ARMCC **5.06 update 4 (build 422)**。工程历史元数据仍写有 ARMCC 5.05，本轮不据此宣称验证过 5.05。HAL 沿用工程现有 1.11.3，仅补齐同版本的 SPI/ADC 9 个官方文件；不升级工具链或整套 HAL。

实施前干预为零的来源快照：311 个文件，ZIP 共 2,190,582 B，SHA-256 `b1a213b66699ef00a8eb11b0f17240dd2f220b1c50f18aa043ea9e34124b8af4`。隔离解压副本的原有 11 个测试入口全部通过，Keil 基线为 0 errors / 0 warnings，Code 84572、RO 3828、RW 452、ZI 94044 B。

最终四目标构建均为 0 errors / 0 warnings。以下来自本轮重新构建的实际日志，与 `Tests/host/build/verification/memory-layout.json` 一致。

| 目标 | Code B | RO B | RW B | ZI B |
|---|---:|---:|---:|---:|
| 默认 UI 关闭 | 87328 | 3828 | 452 | 97684 |
| LCD-ReadOnly | 178720 | 61592 | 768 | 214448 |
| LCD-POS | 182112 | 61592 | 768 | 214448 |
| LCD-MIT | 182112 | 61592 | 768 | 214448 |

Keil 多目标会合并文件组清单，因此基础目标显式排除 Ui/LVGL 组，不能仅省略组条目。`test_debug_ui_build_contract.py` 同时核对组排除、宏值、源文件存在和重复；`--no_multibyte_chars` 保留中文 UTF-8 常量，兼容补丁逐项登记，不全局屏蔽告警。

`check_debug_ui_map.py` 在实际链接 map 中验证：

| 资源 | 链接地址 | 大小/属性 |
|---|---|---|
| 显示缓冲 1 | `0x24000000` | 13440 B，32 B 对齐，Zero RW |
| 显示缓冲 2 | `0x24003480` | 13440 B，32 B 对齐，Zero RW |
| LVGL 内存池 | `0x24008000` | 65536 B，Zero RW |
| UiTask 静态栈 | 从 map 取实际地址 | 8192 B |

显示缓冲位于预留的 AXI 32 KiB 内，互不重叠；UI 关闭目标没有这些资源的链接符号。map 只能证明静态布局，不能给出实际栈使用量、缓存一致性或时序结论。

实际调用图的控制任务已知深度为3152 B，超过原3072 B静态栈。本轮将 Core 和 `.ioc` 中该任务同步增至1280字（5120 B）；ProtocolTask保留5120 B，其已知深度3024 B；UiTask为8192 B，已知深度1040 B。全部任务通过“已知深度 + 512 B余量不超过分配栈”的检查。间接调用与汇编仍含未知项，因此这只是下界检查，不能替代板上高水位测量。

## 独立审查与修正

| 已关闭问题 | 最终行为与证据 |
|---|---|
| 失能未确认后通过改选目标、RELEASE/ACQUIRE或USB hello绕过锁定 | 保留原目标mask和确认时间；所有原目标的新鲜、晚于失败尝试的安全反馈齐全后才允许显式恢复 |
| STOP结果积压阻止物理清理、跨目标STOP遗漏旧目标 | 有界独立停止mask由Arm处理，覆盖活动/排队/原未确认/新增停止目标；已有事务和结果不被丢弃 |
| 延迟结果FIFO的原有uint8回绕覆盖 | 静态容量3改为4以兼容256回绕；每配置自然300组、3600条终态和1200次延迟发布无丢失重复 |
| 远端目标快照错误或额外停止当前浏览的电机 | 取真实活动/待执行mask；ID3场景最终STOP mask=4，多机画面明确数量及位置对应ID |
| 显示恢复后仍被历史错误永久判不健康 | 当前显示有效性与累计SPI/DMA诊断分离；恢复READY可以重新报告健康，历史计数保留 |
| 切模确认内容不区分请求模式 | 明确“实际模式 → 请求模式”，移除与切模无关的运动目标预览 |
| STOP_LATCHED等待不存在的终态，或把故障态当作失能确认 | 此ID不产生异步受理/终态；等待一致快照和全部目标的新鲜、晚于STOP的反馈，且明确driver_state=0、fault_flags=0；故障/未知/旧反馈均显示未确认 |
| DMA释放顺序、屏蔽FEIF、ADC校准边界 | EN未清零时保留SPI/请求/CS和缓冲；按中断使能解释错误；校准超时前复读状态，避免被抢占后误报超时 |

审查均保存触发缺陷的失败输出与修复后结果。全层积压独立案例核对26个原事务的唯一终态（其中10个为取消），65个新增STOP只同步锁存；Protocol停止服务时，Arm仍能产生覆盖目标的失能帧。该结论是软件产帧与结果保留，不是实机停转。
