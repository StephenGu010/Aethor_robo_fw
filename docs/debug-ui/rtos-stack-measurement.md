# RTOS任务栈测量合同

目的：完成P0/P8所要求的七个应用任务栈余量采样，避免仅凭SWD对可缓存RAM的读取作验收结论。此增量不改运动门禁、任务周期、分配栈大小或控制命令。

DiagnosticsTask已有每100ms调用`uxTaskGetStackHighWaterMark()`的循环，继续复用它，同时保存每个任务的最低剩余32位字数和实际分配字数。采样由CPU执行，经现有一致性诊断快照进入ProtocolTask，不由USB请求临时扫描任务栈。

`show diag rtos`保留原有`control_stack`、`can_stack`、`protocol_stack`、`usb_stack`和`heap_min`字段；已采样栈字段表示`剩余字数/分配字数`，未采样继续为`?`。追加`telemetry_stack`、`diag_stack`、`ui_stack`及`stack_unit=words`。UI关闭时`ui_stack=?`。FreeRTOS自身idle任务不包含在这七项应用任务数据内。0字剩余是真实值，不能当作未采样；分配为0或剩余大于分配视为无效样本。

诊断结构保留全局最低栈余量原字段。原有USB客户端仍可忽略新增字段；本地模拟器没有运行RTOS，继续显示未知，不能虚构高水位。

验证必须覆盖：启动未采样、七任务不同容量、零余量、无效容量/越界、UI关闭、快照复制及响应容量。实施后运行受影响回归和完整构建；实机刷写后按实际USB响应计算百分比。此前4523074a版负载不包含本增量，必须单独标识版本证据。

## 当前实现与验证

- 在现有七任务循环中按静态数组实际`sizeof`得到分配字数，复用已有高水位调用，没有增加控制周期内的RTOS栈扫描。
- 应用层对采样发布和对外复制使用已有任务临界区钩子，格式化在临界区外。七个固定样本不分配堆内存。
- Phase0聚合、生产配置、文本协议、App五配置测试通过。主机模拟器同步增加未知字段，继续不产生虚构RTOS读数。
- 行长仍为原协议256字节。当前FreeRTOS默认16位栈深度范围内，七项最大值、最大请求ID及heap值能完整输出；超出此实际范围的七个UINT32最大值合成样本会返回OUTPUT_TOO_SMALL，未输出截断行。此边界已有测试，不扩大协议缓冲来隐藏问题。
- 全部27项检查及四目标Keil构建通过，源码验证期间未变化。只读候选HEX SHA256为`7790eb2cbd60365bdbfe07484343f0fe99b8c54c815309411291861ff03732d6`，ELF为`9e0f31136d2438dd6acb5eaa5899763d9f2afc37eb0041bd54d563ef47e3624f`；243272字节Flash内容逐字节配对一致，固定目录为`output/register-position-20260911/cpu-stack-7790eb2c`（相对TCG根目录）。首次刷写异常退出后，同一工件恢复刷写成功，全部243272字节回读一致。
- `run_stack_load.ps1`将从CPU经USB发出的结果逐项要求至少25%余量，并记录实测最小百分比；物理按键、冷启动和运动工况仍需各自验收。逐文件差异保存在`cpu-stack-review.diff`，不覆盖原先已验证的4523074a工件。
- 60秒实机600条查询全部回复，七个CPU任务栈均超过25%，最低为Protocol 492/1280字（38.4375%）；结果为`stack-load-20260911T034209976-result.json`。随后同一版本30分钟18000条查询全部回复，七任务最低余量仍全部超过25%，Protocol最低467/1280字（36.484375%）。完整日志与报告为`stack-load-20260911T034338923.jsonl`及同名前缀`-result.json`，不覆盖物理翻页或运动工况。
