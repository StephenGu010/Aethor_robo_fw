# LCD-MIT 与单轴 ADRC 同固件集成设计

日期：2026-09-23。用户批准单固件、默认 LCD-MIT、两套运动控制互斥；本阶段仅离线构建，不改写控制板。

## 已核对的基线

- ADRC 基线为 `feature/s3519-adrc` 的 `1cc7e71`，包含三个实际 SLX 模型、生成 C、独立 `ADRC-Bench` 目标及只读电机发现/反馈诊断。
- LCD 流畅度基线为 `feature/lvgl-astra-ui` 的 `1792832`；其改动与 ADRC 分支没有同名文件冲突，已在集成工作树 `feature/s3519-adrc-lcd-mit` 合并为 `a61e8ee`。合并后的原 ADRC 目标 ARMCC 全量重建为零错误、零警告。
- 当前 ADRC 目标在 `AETHOR_ADRC_BENCH=1` 时编译排除传统 LCD/USB 运动服务；LCD-MIT 目标保留它们，但不编译 ADRC 运行时。因此仅合并源码不构成同固件集成。
- 2026-09-23 控制板 USB 只读查询返回 `profile=bench`，`adrc status` 为 `unknown_command`。用户说明板上为新 LCD-MIT 固件；文本协议本身不能区分 LCD-MIT 与其他 bench 构建。本设计不把该查询当作 ADRC 烧录证据。

## 方案比较与选择

1. **一个二进制、显式控制权切换（采用）**：保留 LCD-MIT 默认行为，ADRC 获取选定电机的独占权后才允许其执行帧进入 CAN；STOP 在任一入口都能终止当前所有者。软件复杂度较高，但符合单固件目标。
2. **同源码、两个烧录目标**：现有结构改动小，但用户已明确要求一份固件同时支持两者。
3. **LCD 与 ADRC 并行发帧**：同一电机的模式、发现结果和发送时序会互相覆盖，不满足单轴台架的安全边界。

## 编译与模块边界

- 新建独立 `LCD-MIT-ADRC` Keil 目标及 `AETHOR_ADRC_LCD_INTEGRATED=1` 构建开关。现有 `LCD-MIT` 和 `ADRC-Bench` 目标及其行为保持不变。新目标使用与 LCD-MIT 相同的 LCD/MIT 配置和已合入的流畅度代码，同时包含已验证的 ADRC 生成控制器与独立 CAN 发送回执模块。
- 现有 `MotorRuntime` 是唯一反馈解码与寄存器发现所有者；现有 4 ms `ArmControlTask` 是唯一切换控制权、执行控制循环及选择 CAN 帧的任务。USB 解析和 LCD 任务只提交请求，不能直接发运动帧。
- 控制权在 `LCD`、`ADRC_ACQUIRING`、`ADRC`、`ADRC_RELEASING` 四种状态之间转换。上电默认 `LCD`。一次只允许一个目标电机由 ADRC 持有，其他电机的 LCD 运动请求在 ADRC 持有期也拒绝，以防共享队列和驱动模式争用。
- `adrc acquire motor=7` 是显式转交入口。必须同时满足：LCD 本地控制权已释放；无正在执行或排队的传统运动/模式切换/STOP；CAN 软件队列和硬件发送邮箱均已清空；目标电机有新鲜、无故障、静止且为失能态的反馈；读回身份/量程/当前 MIT 模式与配置一致。任一条件不满足时拒绝并保持 LCD 所有权。转交在控制任务中完成，并使旧发现数据与 ADRC 资格失效后重新读取目标轴。
- ADRC 持有期间，USB 只允许 ADRC 命令及已有只读查询；LCD 保持显示和反馈查看，但 ACQUIRE、POS、MIT 等运动入口拒绝。LCD STOP 与 `adrc stop` 均进入 ADRC 高优先级禁能路径。
- `adrc release` 先终止实验并请求目标轴禁能。只有新鲜、无故障、失能反馈和 CAN 发送完成回执同时成立时，控制任务才把所有权交回 LCD；超时、断线、故障或未知状态均保持运动入口锁定。重启恢复到默认 LCD，但其既有健康、反馈与本地授权门控仍必须重新通过。
- 现有 ADRC 硬件资格仍默认为空。USB 命令不能自称完成辨识、看门狗、映射或模型验证。单固件离线构建不等于准许运动。

## 协议与可观测性

- `adrc status` 增加 `owner=` 字段，并保留已有字段语义；`adrc acquire` / `adrc release` 使用单调请求 ID、同步受理和异步最终结果。重复 ID 不触发二次切换。
- `adrc hardware`、`adrc limits`、`adrc feedback` 在 LCD 所有期仍可只读查询，但不得启动与 LCD 发现流程竞争的独立寄存器序列。ADRC 取得所有权后由其现有 4 ms 路径执行选定轴只读发现与 0xCC 反馈刷新。
- 故障、STOP 和发送回执记录保留操作来源及目标轴；控制权变更、拒绝原因和最终禁能反馈可由协议与离线测试观察。

## 离线验收与实机边界

- 新增纯状态机测试覆盖获取/释放、旧反馈、模式不符、LCD 忙、队列非空、CAN 未空、STOP 竞态、失能确认超时与重放 ID；应用测试覆盖 USB/LCD 双入口无交叉运动帧。
- 现有 LCD、Motor、Phase 0、ADRC 主机回归及 Simulink 生成 C 重放继续通过；Keil `LCD-MIT-ADRC` 全量编译为零错误、零警告，并保存 HEX 哈希与内存用量。必要时测量 4 ms 控制任务在合成最坏输入下的执行时间。
- 本阶段不刷写、不上 24 V、不宣称硬件 ADRC 资格通过。后续实机验收先备份并可恢复当前 LCD-MIT HEX，断开 24 V 后烧录，复位后核对固件身份，再逐步读取 TIMEOUT、反馈周期、失能与映射；辨识和速度抗扰测试须在上述证据成立后开展。
