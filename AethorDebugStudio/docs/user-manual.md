# Aethor Debug Studio 新手手册

适用本版Windows上位机。界面接入、固件部署、离线测试与实机资格分别记录。所有真实动作以当前连接设备的能力和反馈为准。

## 五分钟上手路线

1. 打开工作台，先读顶部“数据来源”。离线演示只使用合成数据；真实设备会访问本地网关；记录回放只查看已导入数据。
2. 运行项目的Start-Studio.ps1，点击“连接设备”，选USB CDC串口，再点“连接并只读查询”。这一步不使能、不运动、不写参数。
3. 连接成功后自动进入“真实设备 · 诊断调试”。进入“单轴静载”或“POS 带载测试”，确认选中ID7，查看“连接与检查”，点击“读取远程能力”。USB已连接不代表电机反馈有效。
4. 设置本次参数，核对转矩保护及启动摘要。“按参数启动一次”会直接推进模式准备及测试，可能使能并产生运动，不是仅审核按钮。首次熟悉界面可先使用离线演示。
5. 测试后看“结果与恢复”，分别核对终态、失能证明和控制权。需要保留数据时到“记录与诊断”导出JSON；不要把网页刷新作为恢复手段。

## 页面地图与数据来源

开始使用：工作台总览查看七轴状态和连接；新手手册支持全文章节搜索、目录跳转和打印。阅读手册不会切换来源或发送动作。

测试与参数：单轴静载执行ID7限时保持；POS带载执行ID7相对移动与到位保持；手动调试提供单次POS、RAM参数和分步操作。七轴调试目前仅有离线演示，真实七轴远程运行尚未接入。

观察与维护：实时示波查看最近60秒信号；记录与诊断导入、导出及回放；驱动与维护查看公开信息和未接入的维护步骤；实验与扩展按状态列出功能。

连接成功会自动切换到真实设备模式，并只读查询；用户也可以用顶部选择器切换来源。顶部“USB已连接”只表示采集链路；标准反馈、位置寄存器、控制权分别核实。演示中的曲线、检查通过和运行结果不能作为设备证据。

## 连接与检查

连接条件：本地网关运行、正确USB串口、设备身份可查询。连接窗口采用115200波特率、DTR/RTS关闭，不自动重连。端口列表为空时检查USB连接、驱动和其他程序是否占用端口，再点“重新枚举”。

真实控制先选ID7。点击“读取配置与CAN诊断”只采集固定诊断；点击“读取远程能力”只查询控制方、当前模式与能力，不启动动作。模式1表示MIT，模式2表示POS；未知时不根据页面名称推断当前模式。

标准反馈提供状态、速度、转矩和温度，年龄超限即失去新鲜资格。0x50寄存器可以按已确认契约换算位置，但不能替代标准反馈或失能证明。0x51原始值仅供诊断，恒零不等于零位。缺少反馈时先检查供电、CAN和身份，不能凭USB连接成功启动。

固件支持静载/POS只表示协议能力；当前能否执行还受控制权、模式、反馈、未结束事务和保护条件约束。板端允许预检意图时，会在DISABLE之后再检查新标准反馈；网页不会把旧寄存器缓存视作测试准入。

## 静载与POS有什么不同

单轴静载：准备MIT模式和静载RAM参数，在当前位置限时保持，用于观察负载与抗扰。真实静载只显示Kp、Kd、前馈与保持时间，没有静载角度或速度目标。保持阶段仍可能发生位置纠偏，不能把“静载”理解成绝不会运动。

POS带载：准备POS模式，相对当前姿态按正负位移移动，到位后保持指定时间，再按固件停止和失能流程结束。使用专用POS带载能力，普通POS不能替代。此操作不使用用户编辑的MIT Kp/Kd/前馈。

手动调试：“本次操作”可以选择普通相对POS、静载配置、保持、模式切换及控制权操作。“下发静载RAM参数”本身不启动保持；“按参数启动一次”会完成该操作需要的前置步骤。高级“审核并冻结”只冻结草稿，“显式提交一次”才发送所选底层操作。

## 参数意义、范围与单位

| 参数 | 作用及输入范围 |
| --- | --- |
| 法兰相对位移 ° | 相对点击启动时的当前姿态；正负号表示方向。POS带载必须非零，最大绝对值以设备本次能力读回为准。不是相对软件零点的绝对目标。 |
| 法兰速度 °/s | POS移动速度，必须大于0且不超过设备本次读回上限；方向由位移正负决定。手动调试页默认使用输出轴°/s。 |
| 输出轴Kp N·m/rad | 位置误差的恢复增益；80～200，真实静载默认120。Kp升高会放大相同误差下的力矩请求，不等于稳定性或负载资格提高。 |
| 输出轴Kd N·m·s/rad | 速度误差阻尼；0.20～0.40，真实静载默认0.30。 |
| 输出轴前馈 N·m | 有符号补偿项，不是实测转矩或持续目标。必须是有限数值；板端还会校验配置与保护范围，不能将保护退出线当作前馈允许值。 |
| 保持时间 s | 1～60秒；静载转换后须为整数毫秒，POS带载要求整数秒。准备和移动时间另计，保持时间不保证一定执行到结束。 |
| 试验转矩退出线 N·m | 新协议可选3.50～6.24，均为电机输出轴；5.46对应峰值7.8的70%，6.24对应80%。草稿和读回分开，未获许可时仍用3.50基线。 |

所有输入必须为有限数值；空白、NaN和无穷值不能提交。设备本次范围小于可编辑范围时，按设备范围拒绝，不静默裁剪。参数编辑和只读查询不发送运动，也不恢复超额余量。

## 坐标与力矩口径

ID7静载/POS页的角度和速度显示法兰端，手动调试默认显示电机输出轴。协议仍使用输出轴rad/rad/s，前端负责换算。已核实映射为转子/输出轴19.2032、转子/法兰44.8，因此输出轴/法兰约2.33294。其他轴不自动套用ID7映射。

转矩、Kp、Kd及保护退出线始终采用电机输出轴口径。法兰角度输入不意味着转矩也变成法兰转矩；本版不通过未验证的传动效率推算负载能力。

示波器可切换“电机输出轴/法兰”显示坐标。0x50位置来源、估算速度、标准反馈和缺失值会分开标识；缺失信号显示空缺，不用零或旧值填补。

## 设零与回零

“当前位置设为零点”只改变本次浏览器会话的软件参考，不写驱动零点、不移动设备。先读取远程能力，要求当前坐标身份有效、无活动事务且控制权空闲。“清除零点”也只改变软件参考。

刷新、重连、主控重启或坐标参考变化后，软件零点失效。

“审核回到零点（运动）”读取独立回零能力，并展示当前原始法兰角度、冻结目标、方向、位移和速度。核对后“显式执行回零一次”才产生真实运动；可用“取消回零审核”取消。审核30秒后或身份变化后失效。

回零不等于普通相对位移。普通POS始终相对当前姿态；回零以已冻结的软件零点为绝对目标。回零不能自动继承静载/POS试验转矩许可。图表和导出记录保留原始坐标，不被软件设零改写。

## 联合保护与短时超额余量

转矩保护与温度、速度、位置、反馈新鲜度和停止链共同作用。不能仅提高温度门槛等待过热；温度反映有延迟，不能约束瞬时机械负荷。35℃恢复、55℃退出是本项目策略，不是厂家额定温度。

未授权退出线为输出轴3.50 N·m。新固件可选3.50～6.24 N·m，只有板端回执及读回确认后才生效。退出线是反馈触发停止的边界，不是连续目标、保证输出力矩或驱动内电流限制。

超额余量是软件累计记录，不是实测热容量。连续超额最多10秒，累计上限175.616 N²·m²·s，按保守邻接样本转矩累计。恒定5.46 N·m约10秒；恒定6.24 N·m约6.58秒即可能耗尽累计余量，其他保护仍可能更早退出。这是软件规则计算，不是厂家持续运行保证。

任一路温度超过55℃退出，恢复要求两路均不高于35℃，并核对低速、低转矩、无故障、新鲜失能反馈、空闲控制权以及同一启动/坐标身份。测试反馈或服务间隔20 ms等其他保护不放宽。

调整草稿、只读查询、结束会话、低于额定运行、刷新或重连都不会返还已用余量；故障撤销许可。恢复操作单次消费令牌，不自动重发，也不会自动启动测试。主控重启不能自动获得冷机身份。旧协议保持固定5.46的兼容提示，不接受新可调写入。

模式2待机可能只更新位置寄存器，标准转矩、温度和失能反馈会过期。先结束原会话，在“转矩保护”读取策略并选择退出线；若唯一阻塞是标准反馈过期，确认本次电机充分冷却、机械臂和负载独立承托，再点击“失能检查并应用试验配额”。它会撤去ID7保持力矩：只发一次失能，读取新标准反馈，通过全部原维护门禁后立即应用并读回。无需切MIT模式，不会使能或启动测试。只有显示“读回确认”和实验退出线后，单轴静载、POS带载才共用该配额；普通POS、回零和其他轴不获得放宽。

若执行前标准反馈已经新鲜，准备流程直接使用原维护门禁，不额外失能。温度、速度、故障或控制权不合格时不会强行恢复。STOP取消尚未发送的维护失能及后续配额恢复；已经发出的失能无法撤销，原回执等待最长4秒。失败或未知不自动重试。

维护失能或配额应用结果未知时，会保留独立维护锁，旧运动终态不能解除。使用“只读核验维护状态”重新读取同一启动及坐标身份、空闲控制权和新鲜失能/冷却证明；缺少证明时继续锁定。该核验只读取，不自动补发失能或恢复配额。

## 审核与启动

依次核对“连接与检查”“设置本次参数”“转矩保护”“审核与启动”的摘要。主按钮“按参数启动一次”是直接执行入口：冻结当前参数、读取设备能力、完成所需模式准备，再执行相应移动或保持并尝试停止/失能和释放控制权。

每一步按原事务编号跟踪，不会自动重发动作。任何失败都会停止继续推进。进行中、未确认结果或失能未确认时参数和新启动保持锁定；页面跳转不会启动新动作，但也不能代替停止。

“高级分步操作”面向已有协议经验的用户，保留申请/释放、模式、预检、配置、冻结和显式提交。普通测试使用主流程即可；不要在原事务未确认时尝试另一操作绕过恢复。

## 正常结束、故障与会话恢复

结果区分别显示测试编号、板端结果和失能证明。completed表示板端回执，不单独证明物理停止；failed表示测试失败，即使失能确认也不等于测试通过。unknown或超时表示本次结果未确认，只能读取原事务，不应重复启动。

先用“恢复最近事务编号”读取网关已保留回执；若网关记录不足，可读取设备能力并点击“恢复设备最近终态 #编号”。再用“读取原事务结果”读取原测试，保留首故障、当时实际退出线和失能证据。不要把故障后的新参数倒推到历史测试。

确认原事务结束及失能后，使用“结束会话／释放控制权”。此按钮核对原事务和连接身份，只提交一次释放，不恢复转矩余量、不启动下一次测试。LCD仍占用时需由LCD按其流程结束；上位机不会抢夺本地控制权。

“STOP 全部轴”是软件停止命令，不能代替硬件急停。“停止 ID n”仅作用于选中轴。反馈不足时停止流程可能转为失能。使用“失能 ID n”前需要独立承托负载并勾选声明，因为失能会撤去保持力矩。失能未确认时继续读取和诊断，不能把断开USB或刷新网页视为已停稳。

## 最近60秒示波、记录与导入导出

“实时示波”在真实模式显示最近60秒，以当前时间推进；反馈断开、来源或启动身份变化会留出缺口，不把旧曲线续成实时反馈。位置、速度、转矩、温度须按坐标与单位分别看。

“记录与诊断”点击“导入 JSON 记录”，支持aethor-studio-recording/v1和static-startup-capture-v1，文件上限2MB。本地解析，不上传云端。导入后是回放，不会给设备下发动作。

记录条目可点“回放”，到实时示波使用“播放回放/暂停回放”和“回放进度”。导出JSON保留结构、来源、未知值与事件；示波器“导出 CSV”按当前显示坐标导出可用采样。合成数据、设备记录和历史导入始终分开，不能互相冒充。

记录存于当前浏览器会话，需要保留时主动导出。软件零点不写入原始坐标。导入启动追踪只把accepted_rx作为已采纳反馈，CAN发送顺序不单独证明驱动接受了目标。

## 驱动维护、规划功能与常见问题

已接入：只读状态、诊断、软件停止/显式失能、ID7单轴静载、专用POS带载、静载RAM参数、独立回零及控制会话恢复。仍须由当前设备报告相应能力，界面入口不等于已部署或实机验证通过。

驱动与维护页只读显示主控公开量程和身份；PMAX写入、驱动保存、重新发现和断电验证未接入该页面。静载RAM参数已接入手动调试，不要与驱动PMAX写入混淆。RAM成功不代表EEPROM保存成功，扩大编码量程不代表机械空间或承载能力扩大。

七轴远程静载、ADRC远程闭环、轨迹编排和多轴联动仍属未接入/实验/规划能力，具体看“实验与扩展”的状态。离线演示仅用于熟悉流程。

为什么按钮不可点：先看是否选中真实模式和ID7、是否连接、是否有原事务未确认、是否正在审核/执行/恢复。回零还需要有效零点与独立能力；转矩恢复还需要空闲失能和冷却条件。按页面给出的阻塞原因处理，不重复点击启动。

为什么有位置却无转矩：可能只有0x50位置寄存器，标准反馈缺失；这不授予运动资格。为什么设零后POS不回零：相对位移仍以当前姿态为起点，要回零必须走独立“审核回到零点（运动）”流程。
